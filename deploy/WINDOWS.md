# Установка на Windows Server одной командой

Адрес приложения по умолчанию: **https://monitoring.btl.local**. Это имя внутри домена `btl.local`; приложение не меняет настройки Active Directory и существующего корневого домена.

1. На сервере скачайте [ZIP проекта](https://github.com/shukhratbekovb/test/archive/refs/heads/main.zip) и распакуйте, например, в `C:\Temp\BTL-source`. Не распаковывайте сразу в `C:\Apps\BTL` — это каталог готовой установки.
2. Нажмите правой кнопкой на `install.cmd` → **Запуск от имени администратора**.
3. По завершении откройте **https://monitoring.btl.local**. Начальные логин и пароль находятся в `C:\Apps\BTL\secrets\initial-admin.txt` (доступ только администраторам сервера). После входа смените пароль.

Альтернатива из **Windows PowerShell от администратора** в распакованной папке:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\install-windows.ps1
```

Нужны x64 Windows Server 2016+ и доступ сервера к python.org, download.microsoft.com и PyPI. Если установка компонентов Windows требует перезагрузки, скрипт остановится с сообщением: перезагрузите сервер и запустите его повторно. На сервере приложение работает без доступа к Интернету после установки.

## Что выполняется автоматически

- Установка IIS, URL Rewrite, ARR и отдельного Python 3.13 для всех пользователей. Загруженные EXE/MSI проверяются по цифровой подписи издателя.
- Копирование кода в `C:\Apps\BTL`, установка проверенных версий зависимостей, запуск тестов.
- Генерация случайного ключа сессий и отдельного начального пароля администратора. Из исходной папки не копируются `.env`, `.venv` и база данных.
- Ограничение NTFS-доступа: код и `.env` доступны службе на чтение; запись разрешена только в `data`, `backups`, `logs`; начальные реквизиты доступны только администраторам и SYSTEM.
- Настройка IIS для доменного имени: HTTP → HTTPS, запросы приложения → Waitress на `127.0.0.1:8080`. Папка IIS содержит только `web.config`; база и секреты не публикуются.
- Выбор установленного сертификата с точным DNS-именем приложения или создание самоподписанного сертификата на год. Приватный ключ не экспортируется.
- Правила Windows Firewall для 80/443 в Domain/Private; внутренний порт 8080 слушает только localhost.
- Автозапуск от `LOCAL SERVICE` при загрузке Windows; перезапуск после сбоя до 10 раз с интервалом в минуту. Ежедневные проверенные копии SQLite от SYSTEM в 02:00 по времени сервера, хранение 30 дней.
- Проверка живого приложения **через IIS и HTTPS**, сертификата, имени сервера, базы и защищённой cookie; первая резервная копия. Для проверки не требуется готовая DNS-запись.

## Два параметра вашей доменной инфраструктуры

Эти настройки выполняются на DNS/в доменной политике, а не в коде приложения:

**DNS.** Создайте в зоне `btl.local` запись **A** с именем **monitoring** и локальным IP Windows-сервера приложения. Если запись уже существует, убедитесь, что она указывает на правильный сервер. Скрипт не изменяет существующие DNS-записи домена. Проверка на компьютере сотрудника:

```powershell
Resolve-DnsName monitoring.btl.local
```

**Доверие HTTPS.** Предпочтителен сертификат корпоративного центра сертификации для `monitoring.btl.local` в `Local Computer → Personal`. Скрипт найдёт его автоматически; конкретный сертификат можно выбрать параметром:

```powershell
.\deploy\install-windows.ps1 -CertificateThumbprint "THUMBPRINT"
```

Если сертификата нет, скрипт создаёт самоподписанный. Для доступа без предупреждений браузера доменный администратор должен распространить **публичный** `C:\Apps\BTL\secrets\btl-server.cer` через GPO: Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities. Самоподписанный сертификат нужно заменить или продлить до истечения срока. Никогда не распространяйте `.env` и `initial-admin.txt`.

## Другой адрес или путь

Если вы хотите именно корневой адрес `https://btl.local` и он не занят другим сайтом/доменной инфраструктурой:

```powershell
.\deploy\install-windows.ps1 -HostName btl.local
```

Можно также задать `-InstallPath D:\Apps\BTL` и `-Port 8081`. При повторном запуске используйте прежние параметры. Не запускайте приложение на контроллере домена без согласования с администратором инфраструктуры; для приложения предпочтителен отдельный сервер.

## Обновление и диагностика

Для обновления скачайте новый ZIP, распакуйте в отдельную папку и запустите установщик с теми же параметрами. Он создаст резервную копию перед остановкой существующего приложения, обновит код и сохранит `.env`, базу, резервные копии и начальные реквизиты. При ошибке обновления изучите сообщение и журналы; автоматический откат кода/схемы не выполняется. Перед обновлением сохраните предыдущий ZIP и скопируйте резервную копию вне сервера.

```powershell
Get-ScheduledTaskInfo -TaskName "BTL Workload Server"
Get-Content C:\Apps\BTL\logs\server.log -Tail 80
Invoke-RestMethod https://monitoring.btl.local/healthz
& C:\Apps\BTL\backup.ps1
```

Журнал приложения автоматически ротируется: 5 МБ, 5 архивов. IIS ведёт свои стандартные журналы. При повторном запуске после неудачной первичной установки используйте ту же папку установки. Не удаляйте `.btl-install.json`: это метка принадлежности установки.

Резервные копии находятся в `C:\Apps\BTL\backups`. Переносите их также на защищённое отдельное хранилище. Для восстановления остановите задачу сервера и убедитесь, что процесс Python остановлен; сохраните текущую базу отдельно, восстановите проверенную копию на путь `DATABASE_PATH`, затем запустите задачу. При откате версии верните и соответствующую версию кода. Не заменяйте SQLite-файл при работающем процессе.

Установка из GitHub создаёт **новую пустую базу**. Рабочая база разработчика и секреты в репозиторий не входят. Перенос существующих данных выполняйте отдельно через проверенную резервную копию.

Настройки IIS основаны на [документации Microsoft по reverse proxy](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/reverse-proxy-with-url-rewrite-v2-and-application-request-routing); установщики — [URL Rewrite](https://www.iis.net/downloads/microsoft/url-rewrite), [ARR](https://www.iis.net/downloads/microsoft/application-request-routing), [Python](https://www.python.org/downloads/release/python-31317/).
